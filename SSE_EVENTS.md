# SSE Events & Notification Triggers

This document lists all Server-Sent Events (SSE) that trigger sound notifications and toast alerts in the Souk Inventory Management System.

## 🔔 Currently Implemented Events

### 1. Alert Resolved ✅ **ACTIVE**
**Event Type:** `alert:resolved`

**Trigger:** When an alert is manually resolved by a user

**Location:** `inventory-backend/src/services/alert.service.ts:124`

**Action:**
- User calls `PUT /api/alerts/:id/resolve`
- Alert status updated to resolved
- SSE event emitted

**Notification:**
- 🔊 **Sound:** Plays notification.mp3
- 🎨 **Toast:** Green success toast with ✅ icon
- 💬 **Message:** "Alert Resolved: {alert_type}"
- ⏱️ **Duration:** 4 seconds

**Data Structure:**
```typescript
{
  id: string;           // Alert ID
  type: string;         // Alert type (LOW_STOCK, CAPACITY_WARNING, etc.)
}
```

### 3. Alert Created 🔔 **NEEDS IMPLEMENTATION**
**Event Type:** `alert:new`

**Should Trigger When:**
1. Low stock detected (automatic reorder triggered)
2. Warehouse capacity warning (>80% full)
3. Warehouse capacity exceeded (>100% full)
4. Order delayed (past expected arrival date)
5. Any system error or critical condition

**Where to Implement:**
- `inventory-backend/src/services/stockMonitor.service.ts` - After creating LOW_STOCK alert
- `inventory-backend/src/services/capacityManager.service.ts` - After capacity alerts
- `inventory-backend/src/services/purchaseOrder.service.ts` - After order delay detection

**Example Implementation:**
```typescript
import { appEvents } from '../utils/eventEmitter';

// After creating alert
const alert = await prisma.alert.create({ data: alertData });

appEvents.emitAlertNew({
  id: alert.id,
  type: alert.type,
  severity: alert.severity,
  message: alert.message,
  metadata: alert.metadata
});
```

**Notification:**
- 🔊 **Sound:** Plays notification.mp3
- 🎨 **Toast:** Color-coded by severity:
  - 🔴 **CRITICAL/ERROR:** Red toast with red border (10s duration)
  - ⚠️ **WARNING:** Yellow toast (6s duration)
  - 🔵 **INFO:** Blue toast (5s duration)
- 💬 **Message:** Alert message from database
- 🎯 **Special:** Critical alerts have bold text and prominent border

### 6. Warehouse Capacity Updated 🏭 **NEEDS IMPLEMENTATION**
**Event Type:** `warehouse:updated`

**Should Trigger When:**
1. Warehouse stock increases (order arrival)
2. Warehouse stock decreases (stock adjustments, transfers)
3. Warehouse capacity threshold crossed (80%, 90%, 95%)

**Where to Implement:**
- `inventory-backend/src/services/stockMonitor.service.ts` - After order arrival
- `inventory-backend/src/services/warehouse.service.ts:48` - After warehouse update
- `inventory-backend/src/services/product.service.ts` - After stock adjustments

**Example Implementation:**
```typescript
import { appEvents } from '../utils/eventEmitter';

// After warehouse update
const warehouse = await prisma.warehouse.findUnique({
  where: { id: warehouseId }
});

const percentage = (warehouse.currentStock / warehouse.capacity) * 100;

appEvents.emitWarehouseUpdated({
  id: warehouse.id,
  name: warehouse.name,
  currentStock: warehouse.currentStock,
  capacity: warehouse.capacity,
  percentage: percentage
});
```

**Notification:**
- 🔊 **Sound:** Plays notification.mp3
- 🎨 **Toast:** Capacity-color-coded:
  - 🔴 **≥90%:** Red toast with border
  - ⚠️ **≥80%:** Yellow/warning toast
  - 🏭 **<80%:** Normal toast
- 💬 **Message:** "Warehouse Update: {name} - {percentage}% capacity ({currentStock}/{capacity})"
- ⏱️ **Duration:** 5 seconds
